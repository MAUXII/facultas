# Worked examples

Four fictional repositories, chosen to pull the skill in four different directions. Each folder has:

- `brief.md`: the repository context, the analysis, the decision, and its limits.
- `README.md`: the README the skill produced.
- any asset the README uses, created as original SVG.

| Example | Category | Composition | Why it differs |
| --- | --- | --- | --- |
| [tessera](tessera/brief.md) | Minimal design-token library | Centered Identity | Mature monochrome mark; nothing a picture explains better than one code sample |
| [loomwork](loomwork/brief.md) | Browser agent framework | Banner-First (diagram banner) | A new loop that a diagram explains faster than prose; no logo, so none was invented |
| [logfmt](logfmt/brief.md) | Rust CLI | Terminal / CLI-First | The product is its output in a terminal; no images at all |
| [driftboard](driftboard/brief.md) | Visual moodboard app | Screenshot-First | The interface is the argument; screenshots are listed for capture, not faked |

All four projects are invented. Nothing here describes a real package, and no screenshot of a running app is included.

Use these to check for convergence: if a new README looks like one of these with a different name, the art direction step was skipped.
